# 通路事件过滤使用说明

<br>

本功能在异常检测前过滤已知不受硬件支持的通路事件，减少由这类事件引起的误告警。过滤只作用于匹配规则的事件，不会关闭整个算子的异常检测。

## 1. 适用范围

通路事件过滤随包含本功能的 MindStudio Sanitizer 一起启用，**没有单独的命令行开关**。当前默认规则要求以下字段同时匹配：

| 字段 | 默认匹配值 |
| --- | --- |
| 计算核 | `AICUBE` |
| 事件 | `MEM_EVENT` |
| 流水线 | `PIPE_S_CAL` 或 `PIPE_S` |
| 内存 | `UB` |
| 访问方式 | `WRITE` |
| 记录类型 | `STORE`、`ST`、`ST_IO`、`STP`、`STI`、`STI_IO`、`ST_ATOMIC` 或 `STI_ATOMIC` |

上述规则覆盖两种流水线表示与八种标量 Store 记录类型的组合。只有同时满足全部条件的事件才会被移除。过滤发生在 Kernel 记录进入 `memcheck`、`initcheck` 或 `racecheck` 的检测器之前；Host 内存记录和其他检测器不使用这条规则。

> [!NOTE]
>
> `initcheck` 使用内存检测的消费路径，因此过滤日志中的消费者名称为 `AddressSanitizer`。`racecheck` 的消费者名称为 `RaceSanitizer`。

## 2. 使用前准备

1. 按《[安装指南](../install_guide/mssanitizer_install_guide.md)》安装包含本功能的完整工具，确保 CANN、编译器与工具版本配套，不要只替换单个动态库。
2. 按算子自身的说明完成编译和输入数据准备，先直接运行算子，确认输出与预期一致。
3. 执行 `mssanitizer --version` 和 `npu-smi info`，确认当前终端调用的是预期工具且设备状态正常。
4. 在可写目录运行检测。开启详细调试日志时，大算子的事件日志可能占用较多磁盘空间。

通路事件过滤无需额外配置。算子的编译选项和工具支持范围仍以《[MindStudio Sanitizer 使用指南](./mssanitizer_user_guide.md)》为准。

## 3. 运行检测

以下是命令格式示例，`./application` 需替换为已经构建的算子程序，并在其后追加该程序需要的参数。示例中的程序名不是仓库提供的可执行文件。

```bash
mssanitizer --tool=memcheck -- ./application
mssanitizer --tool=initcheck -- ./application
mssanitizer --tool=racecheck -- ./application
```

需要分别保存工具输出和检测报告时，可在满足算子数据路径要求的工作目录中执行：

```bash
mkdir -p ./sanitizer-result
MSSANITIZER_ENABLE_DEBUG_LOG=1 INJ_LOG_LEVEL=1 \
  mssanitizer --tool=racecheck --log-level=info \
  --log-file=./sanitizer-result/report.log -- ./application \
  > ./sanitizer-result/tool.log 2>&1
echo "TOOL_EXIT=$?"
```

`--log-file` 指定供用户阅读的检测报告；工具启动信息会提示内部日志位置。开启详细调试日志用于查看过滤统计，不会改变默认过滤规则。若程序依赖相对路径输入数据，应从该程序要求的工作目录运行。

## 4. 查看结果

Kernel 结束时，工具内部日志按消费者和 Kernel 输出实际移除的**事件数**，例如：

```text
Pathway filter consumer:RaceSanitizer, kernel:kernel, deviceId:0, deviceType:36, removed events:1
```

| 输出 | 含义 |
| --- | --- |
| `removed events:1` | 该消费者在当前 Kernel 中移除了 1 条符合规则的事件，不是全进程累计值。 |
| `removed events:0` | 当前 Kernel 没有事件被移除；普通算子或真实错误用例出现 0 属于正常情况。 |
| `====== ERROR:` | 检测器报告的异常。过滤统计与报告错误数是两个指标，不能相加或互相替代。 |
| `TOOL_EXIT=0` | 检测进程正常退出；故意构造错误的算子仍可能同时出现预期的 `ERROR`。 |

同一算子分别用 `memcheck`、`initcheck`、`racecheck` 运行时，每次都是独立检测，不能把多次运行中的 `removed events:1` 加成“一次移除了多条”。汇总脚本也可能重复展示同一条内部日志；核对计数时应查看本次运行的原始日志。

判断功能是否生效，需要同时确认检测器确实完成插桩与事件采集、目标告警的前后变化，以及不匹配规则的真实异常是否仍被报告。单看“无告警”或“退出码为 0”都不够。

## 5. 复验方法

1. 使用同一算子、相同输入和检测模式，分别运行不含本功能的对照工具和包含本功能的工具；两套工具应各自使用完整、配套的安装目录。
2. 对目标通路事件，比较两份 `report.log`，再查看候选工具内部日志的 `removed events`。预期目标告警消失且计数大于 0。
3. 使用真实越界、未初始化读取和数据竞争用例，确认这些不匹配规则的错误仍被检出；再用合法访问用例确认没有新增误报。此类用例的过滤计数通常为 0。
4. 使用大算子评估开销时，固定输入、工具链和设备，分别做多轮预热与配对测量。单次现场耗时不能替代正式性能结论。

有关算子编译、检测模式及异常报告的通用操作，参见《[基础案例](../best_practices/mssanitizer_basic_cases.md)》和《[MindStudio Sanitizer 使用指南](./mssanitizer_user_guide.md)》。

## 6. 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 没有过滤统计 | 确认使用包含本功能的完整工具、详细日志已开启、Kernel 正常结束，并查看工具提示的内部日志目录。不能把“没找到统计”当作移除 0 条。 |
| 目标告警仍出现 | 核对设备、CANN/工具版本、原始算子与输入、检测模式；确认实际事件的六个字段是否全部匹配规则。 |
| 真实错误仍出现 | 这是预期行为；本功能只移除目标通路事件，不会屏蔽其他错误。 |
| 检测无告警但插桩失败 | 检查工具输出中是否有 `E013`、回退原 Kernel、采集为空或报告未完成等信息，不能将其记为过滤成功。 |
| 大算子检测变慢或磁盘增长 | 区分裸算子、开启检测的对照工具与候选工具的耗时；检查详细事件日志大小和写入磁盘。 |

## 7. 限制与回退

- 默认规则只覆盖第 1 节列出的组合，不保证识别其他硬件不支持的通路。规则扩展由工具维护者修改规则表和补充测试完成，不提供用户侧规则配置。
- 本功能没有独立关闭开关。需要对照旧行为时，应在隔离环境使用不含本功能的**完整旧版本**及其配套依赖重新运行，不要混装新旧组件。
- 过滤器复用检测消费者已有的事件副本，并在其上原地移除匹配事件；这不表示整个工具没有分配或复制事件内存。
