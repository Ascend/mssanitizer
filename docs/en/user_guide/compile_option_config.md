# Enabling Full Check

<br>

To enable full check, add the corresponding compilation options to the operator code during compilation and recompile the operator.
The configuration locations of compilation options vary in different operator projects. The following uses [Template Library Scenario](#1-template-library-scenario), [Kernel Launch Symbol Scenario](#2-kernel-launch-symbol-scenario), [msOpGen Operator Project Compilation Scenario](#3-msopgen-operator-project-compilation-scenario), and [Triton Operator Calling Scenario](#4-triton-operator-calling-scenario) as examples.

## 1. Template Library Scenario

Modify the `examples/CMakeLists.txt` file in the template library and add the `-g --cce-enable-sanitizer` compilation option.

```cmake
set(BISHENG_COMPILER_OPTIONS -g --cce-enable-sanitizer)
```

## 2. Kernel Launch Symbol Scenario

1. For details about the sample project code, see the [basic_api_tque_add code example](https://gitcode.com/cann/asc-devkit/tree/9.0.0/examples/01_simd_cpp_api/00_introduction/01_add/basic_api_tque_add). Run the following command to download the sample code of the branch version:

    ```sh
    git clone https://gitcode.com/cann/asc-devkit.git -b 9.0.0
    cd asc-devkit/examples/01_simd_cpp_api/00_introduction/01_add/basic_api_tque_add
    ```

2. To compile the operator code, add the following compilation options:

    - `-g`
    - `--cce-enable-sanitizer` or `--sanitizer`

    Edit the `CMakeLists.txt` file in the sample project directory by referring to the complete sample of kernel function development and running verification. Select the `npu-arch` parameter based on the NPU hardware architecture deployed. For example, for Atlas 950PR/950DT products, change it to `dav-3510`. The `dav-2201` parameter value in this sample applies to Ascend A2/A3 products.

    ```cmake
    target_compile_options(add PRIVATE
        $<$<COMPILE_LANGUAGE:ASC>:--npu-arch=dav-2201 --cce-enable-sanitizer -g>
        # $<$<COMPILE_LANGUAGE:ASC>:--npu-arch=dav-3510>
    )
    ```

    The `--cce-enable-sanitizer` or `--sanitizer` option is added to enable exception check. The two options are completely equivalent, and you can use either one.

    The `-g` option is added to enable the compiler to generate location information. The specific location of the exception (file name, line number, and call stack) will be output in the exception report.

    > [!NOTE]
    > 
    > - If both `--cce-enable-sanitizer` and `-O0` are enabled, the `--cce-ignore-always-inline=false` compilation option needs to be added.
    > - The `-g` compilation option will add debugging information to the generated binary file. You are advised to restrict the access permission of user programs with debugging information to ensure that only authorized personnel can access the binary file.
    > - The operator binary file generated by adding the `--cce-enable-sanitizer` compilation option must be used together with the msSanitizer tool. You are not advised to use this binary file independently. Otherwise, unpredictable problems may occur.
    > - Due to the restrictions of the llvm-symbolizer open-source software, the call stack exception information may fail to be obtained. In this case, you can run the check command again to obtain the exception information about the call stack.

3. To enable the msSanitizer tool, load the executable file `_<kernel_name>__npu` on the NPU. For details about how to obtain the file, see "Kernel Launch Operator Development" > [Kernel Launch](https://www.hiascend.com/document/detail/en/canncommercial/83RC1/opdevg/Ascendcopdevg/atlas_ascendc_10_0056.html) in Ascend C Operator Development Guide.

## 3. msOpGen Operator Project Compilation Scenario

1. Refer to the [link](https://gitcode.com/cann/cann-learning-hub/tree/8.5.0/tutorials/ascendc_operator_development/03_intermediate_vector_operator_development/src/custom_op_04) and prepare the operator project in the `${git_clone_path}/cann-learning-hub/tutorials/ascendc_operator_development/03_intermediate_vector_operator_development/src/custom_op_04` directory.

    > [!NOTE]
    > 
    > This sample project is configured for Atlas A2 products by default. If you use products of another series, modify the following two default configurations:
    > 
    > 1. `ASCEND_COMPUTE_UNIT` in the `CMakeLists.txt` file in the root directory defaults to `ascend910b`. Modify it based on the actual chip model. You can query the Chip Name by running `npu-smi info`. For example, for Atlas 950PR/950DT products, change it to `ascend950`.
    > 2. Modify the value of `.AddConfig("ascend910b")` in the `add_custom_template.cpp` file in the `op_host` directory in the same way.
    > 
    > When downloading the code sample, run the following command to specify the branch version.
    > 
    > ```sh
    > git clone https://gitcode.com/cann/cann-learning-hub.git -b 8.5.0
    > ```

2. Switch to the custom operator project directory.

    ```sh
    cd custom_op_04
    ```

3. Edit the `op_kernel/CMakeLists.txt` file in the sample project directory and add the `-sanitizer` option to the compilation options. For details, see "Operator Compilation and Deployment" > "Custom Compilation Options" in MindStudio Ops Generator User Guide.

```cmake
add_ops_compile_options(ALL OPTIONS -sanitizer)
```

## 4. Triton Operator Calling Scenario

The Triton operator is developed in Python and the kernel is compiled in just-in-time (JIT) mode. Before executing the operator script, configure the following environment variable to support full check:

```sh
export TRITON_ENABLE_SANITIZER=1
```

---

## 5. Verification and Next Steps

After completing the preceding compilation option configuration:

1. Recompile the operator and confirm that the compilation process reports no errors.
2. Use the msSanitizer tool to launch the operator for detection. For details about the usage, see the [MindStudio Sanitizer User Guide](./mssanitizer_user_guide.md).
3. If the file names and line numbers displayed in the detection report are abnormal, see [MindStudio Sanitizer FAQs](../support/mssanitizer_faq.md).
